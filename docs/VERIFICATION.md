## Version 0.3.1 controls and vertex brush

Windows and Linux builds passed all 4 CTest suites. Actual app smoke tests on
both platforms verified vertex painting, Shift erase, unchanged camera during
left brush drags, right-button orbit, Shift+right pan, ignored middle-button drag
in brush mode, wheel zoom and unique camera/tool shortcut assignments. The
front/back-layer fixture verified that hidden vertices were not selected.
Windows also verified that one fast mouse-move event paints an intermediate
vertex between the stroke endpoints. Tests still cover crop, undo/redo and
project persistence after input changes.

The UI was visually inspected from the brush screenshot: orange selected
vertices and the radius circle are visible. The new vertex editing tests confirm
Keep requires all triangle corners, while Delete removes all incident faces.
Redo uses explicit Ctrl+Y and Ctrl+Shift+Z bindings on both platforms to avoid
duplicating Linux's platform-default shortcut. VTK's legacy character commands
are suppressed; Qt actions own the documented bindings.

Brush acceleration data is cached per current mesh and created in a worker.
Large-scan brush interaction latency, pen/tablet devices and broader hardware
depth-buffer behavior still require real-world testing. Control reference:
`docs/CONTROLS.md` (F12 in the app).
